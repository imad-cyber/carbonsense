# CarbonSense

Activity-based carbon accounting for French companies: quantities (kWh, litres, km) multiplied by official ADEME emission factors, with every figure traceable to a factor, a version and a scope.

**Live demo:** TODO-LIVE-URL (read-only; synthetic data for a fictional company)

> A portfolio project, not a compliance tool. All company data in it is synthetic.

## What it does

- **Calculates emissions from activity data.** Quantity × emission factor, with unit handling that refuses unsafe conversions: kWh PCI and kWh PCS are different measurement bases and are never mixed.
- **Uses the official French factor database.** ADEME Base Carbone V23.6 (snapshot of 2025-07-03): 10,939 factors and 5,799 breakdown lines, loaded by `scripts/import_ademe.py`.
- **Books each part of a factor to the right scope.** A fuel or electricity factor includes upstream emissions that are not Scope 1 or 2. Combustion goes to Scope 1 (generation to Scope 2) and the upstream part and grid losses to Scope 3, fuel- and energy-related. Booking the whole factor as direct emissions would overstate it by 19% for natural gas and 24% for road diesel in the demo.
- **Keeps an audit trail.** Every record stores the factor id and version, the value actually used and which part of the factor it came from, so a later factor update cannot silently change an earlier figure.
- **Flags unusual months for review.** Each activity is compared with the same calendar month in other years, on the activity quantity rather than tonnes, so a revised emission factor does not look like an anomaly. Flags are a review queue (the most unusual 5%), not confirmed errors.
- **Forecasts next month** with a transparent baseline (same month last year × trend) and an XGBoost challenger that replaces it only if it beats the baseline in every walk-forward fold by a margin.

- [`docs/VALIDATION_BEGES.md`](docs/VALIDATION_BEGES.md): the Scope 1 and 2 lines of a public greenhouse-gas report (Salesforce.com France, 2023) reproduced from its activity data, with what that does and does not show.

- Unit tests, a migration check on an empty database and a frontend build run in CI on every push.

## Limitations

- All activity data is synthetic. Three anomalies in the demo company were planted by the author, so finding them illustrates the detector and is not a benchmark. Model results are on synthetic data.
- Only the Scope 1 and 2 lines of one published filing are reproduced. One example does not prove the allocation policy right in general.
- Location-based Scope 2 only. Market-based Scope 2, biogenic CO2, organisational boundary (operational control) and district heat factors are not handled.
- Grid losses are booked to Scope 3 following secondary sources; ADEME's own guidance has not been checked.
- Forecasts exist only for the month right after the latest data.
- Emission factors are a July 2025 snapshot; newer releases would be imported as new versions.

## Run it locally

```bash
python -m venv venv && venv\Scripts\activate        # use `source venv/bin/activate` on Linux or macOS
pip install -r requirements.txt
cp .env.example .env                                 # set DATABASE_URL and a new SECRET_KEY
alembic upgrade head
python scripts/import_ademe.py fetch                 # downloads Base Carbone from data.ademe.fr
python scripts/import_ademe.py load
python scripts/generate_training_data.py             # five synthetic companies (tonnes entered directly)
python scripts/seed_demo_company.py                  # the demo company, from activity data
python scripts/seed_demo_user.py                     # read-only demo login
python scripts/train_models.py
python scripts/evaluate_models.py
uvicorn app.main:app --reload
cd frontend && npm install && npm run dev            # http://localhost:5173
```

Tests: `pytest`. The deployed image uses `requirements-api.txt` (only what the API imports) and the committed `models/*_latest.joblib`.
